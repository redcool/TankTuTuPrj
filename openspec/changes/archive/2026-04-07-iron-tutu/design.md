## 上下文

本项目是Unity 3D俯视角roguelike射击游戏，类土豆兄弟玩法，主角为6槽位战车，支持最多4人同屏合作。

**当前状态**：
- Unity 2022.3 + URP渲染管线已配置
- 基础资源已导入：SUV战车（含6个Slot节点）、4种Blaster武器、2种怪物模型
- InputSystem已安装

**约束**：
- MVP阶段仅1辆战车、4种武器、3种怪物
- 地图范围固定在摄像机一屏内
- 性能目标：1000批次内流畅运行
- 需要支持Steam云同步存档

**利益相关者**：单人开发，AI辅助编码

## 目标 / 非目标

**目标**：
1. 实现完整的游戏循环：开始界面 → 战斗 → 结算 → 商城 → 下一关
2. 战车6槽位武器自动安装机制
3. 4人同屏合作（各手柄控制各自战车）
4. 武器自动瞄准射击
5. 资源收集系统（击杀掉落 → 靠近收集）
6. 抽卡与商城系统
7. 本地存档 + Steam云同步
8. 战车15种数值属性的影响

**非目标**：
- 多人网络联机（仅本地同屏）
- 复杂的地图生成（MVP固定场景）
- 战车外观定制（仅数值变化）
- 成就系统
- 排行榜

## 决策

### 1. 输入系统架构
**决策**：使用Unity InputSystem，支持最多4个手柄
**理由**：InputSystem原生支持多设备识别，比旧InputManager更适合多人场景
**替代方案**：
- 旧InputManager：需要自己处理多手柄映射，不推荐

### 2. 战车控制方案
**决策**：摇杆控制移动方向，战车自动转向移动方向
**理由**：简化操作，让玩家专注武器选择和站位
**替代方案**：
- 摇杆移动 + 另一个摇杆瞄准：会增加操作复杂度

### 3. 武器系统架构
**决策**：6个独立WeaponSlot组件，武器作为子对象挂载到Slot
**理由**：灵活支持不同类型武器的安装/卸下
**数据结构**：
```csharp
TankData {
    maxHealth, healthRegen, lifesteal,
    percentDamage, rangedDamage, meleeDamage, elementDamage, engineering,
    attackSpeed, critRate, range, armor, dodge, moveSpeed, luck, harvest
}
WeaponData {
    type: Melee/Ranged/Element,
    damage, attackSpeed, range,
    projectilePrefab, muzzlePosition
}
```

### 4. 武器自动瞄准
**决策**：每把武器独立寻找最近目标，独立射击冷却
**理由**：实现简单，且能产生多武器交叉火力的效果
**替代方案**：
- 集中瞄准系统：所有武器攻击同一目标，但会增加复杂度

### 5. 资源收集方式
**决策**：能量块掉落在尸体位置，玩家靠近触发收集（无需按键）
**理由**：简化操作，符合土豆兄弟手感
**替代方案**：
- 手动按键拾取：增加操作负担

### 6. 存档方案
**决策**：JSON文件存储在Application.persistentDataPath，支持SteamCloud同步
**理由**：简单可靠，SteamWorks自动处理云同步
**数据结构**：
```csharp
SaveData {
    version: int,
    unlockedTanks: List<string>,
    unlockedWeapons: List<string>,
    unlockedItems: List<string>,
    stats: { totalKills, totalPlayTime, ... }
}
```

### 7. 抽卡概率
**决策**：基础概率 + 幸运值修正，保底机制
**理由**：玩家可感知幸运值的作用，刺激消费
**公式**：
- 基础稀有度概率：N=70%, R=25%, SR=4%, SSR=1%
- 幸运修正：每点幸运 +1% SR概率，+0.5% SSR概率

### 8. 数值体系
**决策**：使用价值点体系，属性价格 = 价值权重 × 基础价值
**理由**：与土豆兄弟保持一致的数值感受
**换算**：1价值点 ≈ 10金币

## 风险 / 权衡

### 风险：4人同屏性能
**→ 缓解措施**：
- 对象池化：子弹、伤害数字、特效
- 共享材质：减少DrawCall
- 限制同屏怪物数量（最多50只小怪 + 1只Boss）

### 风险：InputSystem多手柄识别
**→ 缓解措施**：
- 动态分配PlayerIndex，基于连接顺序
- 手柄断开时自动回收并重新分配

### 风险：武器AI瞄准性能
**→ 缓解措施**：
- 每0.1秒更新一次目标（不是每帧）
- 距离检测使用平方距离（避免开方）

### 风险：存档同步冲突
**→ 缓解措施**：
- MVP阶段使用"最后写入胜出"策略
- SteamCloud会自动处理基本的冲突

### 风险：战车属性对游戏平衡影响
**→ 缓解措施**：
- MVP先锁定所有属性为基准值
- 后续通过商城购买逐步开放
